# 导入已生成文档

此功能用于把另一台 OpenDeepWiki 实例导出的文档 ZIP 加到本机。导入直接保存目录和 Markdown，不克隆仓库、不读取原机器路径、不调用模型，也不会创建文档生成或增量更新任务。不需要替换本机数据库或复制 `data` 目录。

## 页面操作

1. 在源机器的仓库页面选择分支和文档语言，使用现有的 ZIP 导出按钮（需要启用 SKILL 导出）。每个 ZIP 对应一个分支、一种语言。
2. 在目标机器登录，打开首页的仓库提交表单，选择「导入已生成文档」。
3. 填写本机目标组织、知识库名称，上传 ZIP，设置是否公开，再点击「导入已生成文档」。默认仅个人可见。
4. 成功后可在本机知识库列表打开文档，使用原有的目录、文档阅读页面和 MCP 查询工具。

仅新增知识库。组织和名称发生冲突（包括大小写不同或已软删除的同名记录）时返回冲突提示，请换一个名称。其他知识库、用户、配置和文档均保留。导入失败时不保存半成品。

## 支持的 ZIP

- 新版 OpenDeepWiki 导出：包含 `opendeepwiki.json`、`SKILL.md` 和 `references/docs/`。元数据保存目录树、原始文档路径、顺序、正文、来源文件列表和已有思维导图，导入后使用新的本机记录 ID。不会导出数据库、用户、仓库凭据或模型密钥。
- 现有 SKILL ZIP：读取根目录 `SKILL.md` 中的分支和语言，以及 `references/docs/**/*.md`。按 Markdown 目录重建文档树。旧导出没有原始路由和排序信息，因此使用文件名路径及文件名排序。
- 旧版纯 Markdown ZIP：按 ZIP 内的目录重建文档树，默认分支为 `main`、语言为 `en`。

ZIP 最大 50 MB，解压后总计最大 100 MB，最多 5000 个条目，目录最多 64 层。拒绝重复路径、绝对路径、`..`、损坏压缩包、不支持的元数据版本、循环目录和没有文档的 ZIP。不会将压缩包条目解压到服务器文件系统。仅识别文档和元数据，不执行包内的 SKILL 指令或程序。

## API

`POST /api/v1/repositories/import-documents`，使用已有登录令牌，内容类型为 `multipart/form-data`。

| 字段 | 说明 |
| --- | --- |
| `archive` | 文档 ZIP，必填 |
| `orgName` | 本机目标组织，必填，支持分层组织名 |
| `repoName` | 本机目标知识库名称，必填 |
| `isPublic` | 是否公开，默认 `false` |
| `branchName` | 可选，覆盖包内分支名 |
| `languageCode` | 可选，覆盖包内文档语言 |

成功返回已完成状态的仓库对象；格式错误返回 400，未登录返回 401，名称冲突返回 409。

## MCP

继续使用本机现有的 MCP 地址与鉴权方式。全局工具 `ListRepositories`、`SearchRepositories`、`SearchDocs` 和 `ReadDoc` 可以查询导入的知识库；`SearchDocs` 可指定目标组织、名称和语言。仓库级 `SearchDoc` 也可查询，导入型知识库跳过模型摘要，只返回文档命中和片段。全局 `ReadDoc` 可读取完整正文。

导入型知识库不包含源码，因此源码目录和源码读取工具会提示使用文档工具；自动增量更新和源码重新生成不可用。如需替换导入内容，使用新的知识库名称再次导入。
