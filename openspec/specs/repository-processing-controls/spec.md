# repository-processing-controls Specification

## Purpose

让仓库所有者与管理员能够对仓库级 wiki 生成处理进行干预:暂停并断点继续、停止、或清空后重新开始,从而在长耗时、占用集群生成槽位的处理过程中获得直接控制权。

## Requirements

### Requirement: 暂停仓库处理

系统必须(MUST)允许有权用户暂停处于 Pending 或 Processing 状态的仓库处理。暂停请求生效后,处理必须在短暂延迟内(下一个执行检查点)停止推进,而不得继续跑完整个处理;仓库状态必须变为 Paused,已生成的目录与文档内容必须保留,且必须释放其占用的集群生成槽位与仓库生成锁。

#### Scenario: 暂停处理中的仓库
- **WHEN** 有权用户对一个 Processing 状态的仓库请求暂停
- **THEN** 处理在检查点停止推进,仓库状态变为 Paused,已生成内容保留,生成槽位与锁被释放

#### Scenario: 暂停排队中的仓库
- **WHEN** 有权用户对一个 Pending 状态的仓库请求暂停
- **THEN** 仓库状态变为 Paused,处理不会被调度执行

#### Scenario: 对不可暂停的仓库请求暂停被拒绝
- **WHEN** 对 Failed、Completed、Stopped 或已 Paused 状态的仓库请求暂停
- **THEN** 操作被拒绝并返回明确的错误信息,仓库状态不变

### Requirement: 从暂停继续处理

系统必须(MUST)允许有权用户对 Paused 状态的仓库执行「继续」。继续后仓库重新进入调度,并在执行时从断点恢复:此前已持久化的文档不得重新生成,已生成内容必须原样保留。目录允许重新生成以保证完整性。

#### Scenario: 继续已暂停的仓库
- **WHEN** 有权用户对一个 Paused 仓库请求继续
- **THEN** 仓库重新进入调度并恢复处理,且此前已持久化的文档不被重新生成

#### Scenario: 对非暂停仓库请求继续被拒绝
- **WHEN** 对非 Paused 状态的仓库请求继续
- **THEN** 操作被拒绝并返回明确的错误信息

### Requirement: 停止仓库处理

系统必须(MUST)允许有权用户停止处于 Pending、Processing 或 Paused 状态的仓库处理。停止请求生效后,执行必须在短暂延迟内(下一个执行检查点)终止;仓库状态必须变为 Stopped,已生成的内容必须保留,并必须释放其占用的集群生成槽位与仓库生成锁。

#### Scenario: 停止处理中的仓库
- **WHEN** 有权用户对一个 Processing 仓库请求停止
- **THEN** 执行在检查点终止,状态变为 Stopped,已生成内容保留,槽位与锁被释放

#### Scenario: 停止已暂停的仓库
- **WHEN** 有权用户对一个 Paused 仓库请求停止
- **THEN** 仓库状态变为 Stopped

#### Scenario: 对已结束仓库请求停止被拒绝
- **WHEN** 对 Failed、Completed 或 Stopped 状态的仓库请求停止
- **THEN** 操作被拒绝并返回明确的错误信息

### Requirement: 重新开始仓库处理

系统必须(MUST)允许有权用户对任意状态的仓库请求「重新开始」:清空该仓库已生成的目录与文档内容,并将其重新排入处理队列(Pending),按全量生成重新处理。对正在处理中的仓库,必须先终止当前执行,再清空并重新排队。

#### Scenario: 重新开始处理中的仓库
- **WHEN** 有权用户对一个 Processing 仓库请求重新开始
- **THEN** 当前执行被终止,已生成内容被清空,仓库重新排队并开始全量生成

#### Scenario: 重新开始已停止的仓库
- **WHEN** 有权用户对一个 Stopped 仓库请求重新开始
- **THEN** 已生成内容被清空,仓库重新排队并开始全量生成

#### Scenario: 重新开始已完成的仓库
- **WHEN** 有权用户对一个 Completed 仓库请求重新开始
- **THEN** 行为与现有「重新生成」一致:清空后全量重跑

### Requirement: 控制操作的权限

仓库处理控制操作(暂停、继续、停止、重新开始)必须(MUST)仅允许该仓库的所有者本人或系统管理员执行。未认证用户必须被拒绝(401);已认证但无权限的用户必须被拒绝(403),且仓库状态不得改变。

#### Scenario: 仓库所有者操作自己的仓库
- **WHEN** 仓库所有者对自己的仓库执行任一控制操作
- **THEN** 操作被接受

#### Scenario: 管理员操作他人仓库
- **WHEN** 管理员对任意仓库执行控制操作
- **THEN** 操作被接受

#### Scenario: 无权限用户被拒绝
- **WHEN** 非所有者、非管理员的已登录用户执行控制操作
- **THEN** 请求被拒绝(403),仓库状态不变

### Requirement: 并发状态守卫

控制操作与处理执行可能并发发生。状态变更必须(MUST)使用条件更新(仅当仓库处于该操作允许的源状态时才生效)。当处理在操作生效前恰好完成或失败时,终态不得被控制操作覆盖,操作必须返回冲突错误。对同一状态重复提交的操作必须被拒绝并给出明确错误信息。

#### Scenario: 暂停请求与处理完成竞争
- **WHEN** 仓库在暂停请求生效前恰好处理完成
- **THEN** 仓库保持 Completed 状态,暂停操作返回冲突错误

#### Scenario: 对状态已变更的仓库重复操作
- **WHEN** 对一个已处于 Paused 的仓库再次请求暂停
- **THEN** 操作被拒绝并返回明确的错误信息,状态保持 Paused

### Requirement: 处理页控制交互

仓库处理页必须(MUST)根据仓库当前状态展示可用的控制操作,并正确呈现 Paused 与 Stopped 状态;控制操作完成后页面必须刷新到最新状态。控制操作必须仅对有权用户(所有者或管理员)可用;无权用户仍可查看处理进度。

#### Scenario: 处理中展示控制操作
- **WHEN** 有权用户打开一个 Processing 仓库的处理页
- **THEN** 页面显示暂停、停止与重新开始操作

#### Scenario: 暂停后展示继续操作
- **WHEN** 仓库处于 Paused 状态
- **THEN** 页面显示继续、停止与重新开始操作,并明确提示已暂停

#### Scenario: 停止后展示重新开始操作
- **WHEN** 仓库处于 Stopped 状态
- **THEN** 页面显示重新开始操作,并明确提示已停止

#### Scenario: 无权用户不显示控制操作
- **WHEN** 无权用户打开处理页
- **THEN** 页面不显示控制操作按钮,但进度展示正常

### Requirement: 生成槽位与锁的释放

因暂停或停止而终止的处理必须(MUST)释放其占用的集群生成槽位与仓库生成锁,使其他排队仓库能够获得槽位继续执行;系统不得出现已暂停或已停止仓库长期占用槽位的情况。

#### Scenario: 暂停后其他仓库获得槽位
- **WHEN** 一个仓库被暂停且集群生成槽位此前已被占满
- **THEN** 其他 Pending 仓库能够在后续调度中获得槽位

#### Scenario: 停止后槽位释放
- **WHEN** 一个仓库被停止
- **THEN** 其占用的槽位与锁被释放
