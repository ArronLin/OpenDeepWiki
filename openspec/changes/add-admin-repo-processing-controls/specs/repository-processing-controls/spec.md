# Spec Delta: repository-processing-controls

## ADDED Requirements

### Requirement: 管理后台详情页控制交互

管理后台仓库详情页必须(MUST)按仓库当前状态提供与处理页一致的控制操作矩阵(暂停/继续/停止/重新开始),并由该矩阵承载详情页的单仓重新开始能力。页面必须正确显示 Paused 与 Stopped 状态(本地化名称与状态标识);仓库处理活跃时页面必须周期性自动刷新状态与进度。控制操作成功后页面必须立即刷新到最新状态,操作进行中必须给出进行态反馈,操作被拒绝时必须给出明确错误信息并刷新状态。重新开始为破坏性操作(清空已生成内容),执行前必须要求用户确认。

#### Scenario: 处理中仓库显示控制操作
- **WHEN** 管理员打开一个 Processing 状态仓库的详情页
- **THEN** 页面显示暂停、停止与重新开始操作

#### Scenario: 暂停后展示继续与本地化状态
- **WHEN** 仓库处于 Paused 状态(打开详情页或暂停操作成功后)
- **THEN** 页面显示继续、停止与重新开始操作,且状态以本地化的"已暂停"标识呈现

#### Scenario: 已停止或已结束仓库展示重新开始
- **WHEN** 仓库处于 Stopped、Failed 或 Completed 状态
- **THEN** 页面显示重新开始操作作为单仓重跑入口

#### Scenario: 重新开始前必须确认
- **WHEN** 管理员在详情页点击重新开始
- **THEN** 页面弹出确认提示;确认后执行清空并重新排队,取消则不执行且仓库状态不变

#### Scenario: 控制操作成功后自动刷新
- **WHEN** 管理员在详情页执行控制操作成功(如暂停)
- **THEN** 页面无需手动刷新即反映最新状态与对应的操作矩阵

#### Scenario: 处理活跃时自动刷新进度
- **WHEN** 详情页打开且仓库处于 Pending 或 Processing 状态
- **THEN** 页面周期性自动刷新状态与处理进度,直至仓库进入不再活跃的状态

#### Scenario: 操作被拒绝时提示并刷新
- **WHEN** 控制操作因状态冲突或其他原因被拒绝
- **THEN** 页面给出明确错误信息并刷新到仓库当前状态
